# GUI 界面结构与设置分级

本项目只有「迷失之地」和「战斗助手」两个功能，GUI 按「少入口、配置和开始在同一屏」组织。新增界面或设置项时按本文放置。

## 导航结构

入口在 `src/zzz_lv/gui/app.py` 的 `create_sub_interface`。

| 位置 | 导航项 | 界面类 | 内容 |
|---|---|---|---|
| 顶部 | 主页 | `HomeInterface` | 运行准备状态卡片 + 迷失之地 / 战斗助手两张功能卡片 + 快捷键提示，见下方「主页」 |
| 顶部 | 迷失之地 | `LostVoidInterface` | 只有「运行」一个 tab（挑战配置随刷取目标自动切换，不给用户编辑） |
| 顶部 | 战斗助手 | `BattleAssistantInterface` | 自动战斗、闪避助手切换，配置 + 开始/停止 + 日志 |
| 顶部 | 画中画 | `PipButton` | 开关按钮，不是页面 |
| 底部 | 开发工具 | `AppDevtoolsInterface` | 只在开发者模式下显示 |
| 底部 | 资源管理 | `ResourceManagementInterface` | 模型下载、下载源、网络代理；没开「显示高级设置」时隐藏 |
| 底部 | 设置 | `AppSettingInterface` | 游戏设置 / 悬浮层 / 脚本环境 / 推送 / 自定义 |

### 主页

不用背景图，按 Fluent 设置页的卡片风格排版，从上到下：

1. 标题区：项目名 + 一句话说明，右侧 GitHub 链接。
2. 运行准备卡片：调用 `check_pre_flight`。全部就绪时只显示一行「准备就绪」；有问题时逐条列出，每条带「前往」按钮跳到对应设置页。
3. 两张功能卡片并排：
   - 迷失之地：显示挑战副本、挑战配置（按刷取目标自动选的内置配置名）、刷取目标、本周通关次数；「配置」跳到迷失之地页，「开始运行」先做准备检查再跳到运行页并开始，运行中改为「查看运行」。
   - 战斗助手：显示战斗配置、闪避方式、后台模式；「打开战斗助手」跳到战斗助手页。
4. 快捷键提示：开始/暂停、停止的按键。

启动时 ctx 在后台初始化，迷失之地配置要等应用注册完才能读：卡片先显示「加载中…」，`app_setting_manager.ready` 信号到达后再刷新。

主题色：不再从背景图取色。未开启「设置 → 自定义 → 自定义主题色」时用默认蓝色 `(0, 120, 215)`，开启后用保存的颜色；启动时在 `app.py` 的 `main()` 里设置。

### 迷失之地

- **运行**（`LostVoidRunInterface`）：左侧放常用配置（挑战副本、刷取目标、计划刷取次数、活性增幅、运行记录、预备编队、结束后、深度避障），右侧是开始/停止和日志。
  - 刷取目标只有 3 个：完成悬赏委托 / 刷满业绩点 / 战线肃清。挑战配置按目标自动映射到内置「通关效率」「菲林收集」，没有每天次数限制。周常目标跑到本周完成；菲林目标自动使用战线肃清·难度五，暂时禁用副本下拉，切回周常后恢复原副本。
  - 战线肃清目标目前辅助收集，页面显示待核对原因和「战线肃清奖励核对」按钮，列出尚未接入完整识别与领取的奖励。找不到可刷战略时按未完成退出，不报告全部完成。详见 [迷失之地自动化](application/lost_void/README.md)。
  - 「结束后」沿用 `one_dragon_config.after_done`，运行线程结束后调用 `execute_after_done`，只在正常跑完时执行。
  - 「深度避障」开关（`depth_avoid_enabled`）在「结束后」下面，寻路时用深度模型提前绕开障碍物，详见迷失之地自动化文档。
  - 没打开游戏时，`Operation` 自带的「检测游戏窗口 → 打开并进入游戏」节点会按「设置 → 游戏设置」里的游戏路径、区服、账号自动启动并登录，不需要单独开关。
  - 「预备编队」分组：选编号「编队 N」（默认「不选择」）和 1~3 号位成员（下拉选代理人）。编号为「不选择」时成员置灰。配置存在迷失之地应用配置（`predefined_team_no` / `team_agent_id_1~3`）。
- 战线肃清和特遣调查按运行页的预备编队编号选队，没选时沿用游戏当前编队；矩阵行动沿用游戏当前主战编队，未识别到主战编队时提示先在游戏内选择。上游的「挑战配置」「预备编队」编辑页已去掉。

### 去掉的上游页面

一条龙、应用运行在本项目里都只能运行迷失之地，和迷失之地运行页重复；账户管理（多账号）只服务于一条龙的「全部账号轮流跑」。三个页面都已去掉：

- 游戏路径、区服、自动登录账号搬到「设置 → 游戏设置」顶部的「游戏」分组，读写当前实例的 `game_account_config`。
- 应用层的 `ZOneDragonApp` 和框架层的 `OneDragonRunInterface` / `StandaloneRunInterface` / `SettingInstanceInterface` 保留，CLI 和后端仍可使用。

## 设置项三档分级

每个设置项按「普通用户多久改一次」放到下面三档之一：

| 档位 | 放法 | 例子 |
|---|---|---|
| 常用 | 直接显示 | 挑战副本、战斗配置、闪避方式、后台模式、按键 |
| 高级设置 | 放进页面里的 `ExpandSettingCardGroup`，标题「高级设置」，默认折叠 | 战斗助手的 GPU 运算、截图间隔、终结技一好就放；悬浮层的字体、透明度、刷新间隔 |
| 显示高级设置 | 按 `ctx.env_config.advanced_mode` 控制显隐，见下方「高级设置开关」 | 迷失之地页的挑战副本、深度避障；资源管理页 |
| 开发者模式 | 按 `ctx.env_config.developer_mode` 控制显隐 | 战斗状态面板、使用合并配置文件、战斗/闪避配置删除按钮；悬浮层的调试面板、视觉绘制、性能指标、截图补丁；脚本环境的调试模式、截图键、调试键；整个开发工具页 |

判断依据：

- 改错了会让功能跑不起来、且普通用户能理解的 → 常用。
- 普通用户能理解但一般保持默认就行的调参 → 高级设置。
- 只在调试模板、排查识别问题、开发新功能时才用的 → 开发者模式。

### 开发者模式显隐的刷新方式

- 开发者模式在「设置 → 脚本环境」里开关，或连点标题栏版本号 7 次打开。切换时主窗口 `MainAppWindowBase._apply_developer_mode_visibility` 会调用每个**顶层导航页**的 `_update_developer_visibility()`。
- 顶层导航页（如 `BattleAssistantInterface`）实现 `_update_developer_visibility()`，并在 `on_interface_shown` 里也调一次。
- tab 里的子页面（如设置下的各 tab）不会收到主窗口的调用，在自己的 `on_interface_shown` 里按当前开关刷新即可：切换开发者模式后再切到这个 tab 就会刷新。

### 高级设置开关（发布包默认关闭）

免安装发布包给不想研究配置的用户用，只露核心功能，其余用默认值。源码运行不受影响，默认全部显示。

- 开关是 `env_config.advanced_mode`，在「设置 → 脚本环境」的「显示高级设置」。默认值由 `os_utils.get_release_version()` 决定：包根目录有打包脚本写入的 `release.json`（发布包）就默认关，没有（源码运行）就默认开。
- 切换时 `MainAppWindowBase._apply_advanced_mode_visibility` 调用每个顶层导航页的 `_update_advanced_visibility()`，写法和开发者模式相同。`AppWindow` 额外重写它来隐藏资源管理导航项（发布包已带模型）。
- 迷失之地页关闭高级设置时隐藏「挑战副本」（跟随刷取目标，默认战线肃清）和「深度避障」（默认开）。刷取目标、计划刷取次数、活性增幅、预备编队、结束后仍然显示。
- 「高级设置」和「开发者模式」是两档：前者是给普通用户的进阶选项，后者是开发调试用的，互不包含。

### 首次运行快速设置

`FirstRunGuideDialog`（`src/zzz_lv/gui/view/home/first_run_guide_dialog.py`）：发布包（`advanced_mode` 关闭）第一次运行，在使用须知弹窗关闭、`AppSettingManager.ready` 信号到达（应用配置可读写）之后弹出，只问刷取目标、计划刷取次数、预备编队三项，选项直接写进迷失之地配置。完成后 `env_config.first_guide_done` 置为真，不再弹。
