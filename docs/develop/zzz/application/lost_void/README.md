# 迷失之地自动化

玩法规则见 [迷失之地玩法](../../../../game/gameplay/迷失之地.md)，已建档的画面见 [迷失之地画面](../../../../game/screens/迷失之地.md)。本页说明自动化的范围和完成判定。

## 刷取目标

- 完成悬赏委托：沿用用户选择的副本，入口显示 `8000/8000` 后停止并领取悬赏奖励。
- 刷满业绩点：沿用用户选择的副本，在完整的挑战结果画面核对是否还有零号业绩奖励。
- 获取大部分菲林奖励（旧名「获取所有菲林奖励」「战线肃清」，旧配置读取时自动改名；下文和代码里的「菲林目标」指它）：按[速刷图鉴教程](../../../../game/gameplay/迷失之地.md#速刷图鉴策略教程)，自动进入战线肃清并选择配置的难度（默认难度五），使用内置收集配置，优先尚未完成收集的调查战略、通用武备与 NEW 藏品，局内按下文「菲林目标的局内策略」选择。这是目前可自动推进的部分，不代表能够自动完成所有奖励。

前两项目标使用内置「通关效率」，菲林目标使用「菲林收集」。用户不需要编辑挑战配置；预备编队可选（见下文「运行记录与配队」）；周常副本选择保留。菲林目标自动选择战线肃清，不覆盖用户保存的周常副本。

## 菲林奖励的核对范围

全部奖励包含常规副本首通和以太活性奖励、周期玩法任务、调查进度等级奖励、探究勋证、武备/鸣徽/卡牌图鉴、探究记录中的特殊条件任务，以及特殊行动、溯影行动、祸首歼灭战和相关成就。

现有画面资料没有这些页面的完整状态和领取流程，因此程序不能逐项自动确认完成，也不会写入「全部菲林已完成」。运行页和日志明确说明这一限制。调查战略和武备的追新选择只用于选择下一局内容；滑动次数、轮廓数量和没有看到 NEW 都不能证明奖励已经拿完。

没有找到可继续刷取的调查战略时，程序记录原因、返回大世界，并以未完成状态结束。识别失败也按未完成处理。两种情况都不触发正常完成后的关机等动作。后续运行仍会重新识别，不依赖上一次的错误完成标记。

周常目标沿用游戏内已有难度设置；菲林目标在战线肃清画面自动切到运行页「难度」选的难度（配置项 `polychrome_difficulty`，难度一~六，默认难度五；节点「选择难度」：标题不含目标难度时打开难度列表点它，用「包含」判断，因为 lcs 匹配会把别的难度也当成命中；列表里没有该难度，例如难度六未解锁，节点重试耗尽后失败）。各奖励的实际条件以游戏任务说明为准。没有足够画面依据的任务保留为未支持，不用猜测的按钮坐标补流程。

## 调查战略追新选择

追新模式先向左拖到列表开头，再向右逐页检查，一直拖到最右边、看完整个列表后才选；每次拖动约 1500 像素（原来 800 像素只移动 3 个战略），拖动后都重新截图。用已识别战略的名称和横坐标判断列表是否继续移动，不按固定拖动次数结束。看完后选已确认等级最低的战略（黑色空圆圈的未收集战略算 0 级，自然最先选），同等级按战略列表顺序选第一个；选中后按名称拖回去点击。（2026-10-22 实测原来看到第一个未收集战略就选，右边的战略从没露出来。）

等级圈圈只用于定位。白色数字从圆圈内部提取：8 的字形有两个封闭孔，直接按满级排除；其余交给单字 OCR，只有明确读出的 0～7 才能参与选择。黑色空圆圈必须同时通过无等级圈圈检测且内部没有白色数字，不能把普通等级圈圈的识别失败当成零进度。忽略不完整圆圈和背景轮廓，识别失败的候选跳过并记日志。

没有可确认的候选时，菲林目标沿用待核对出口，其他追新目标按失败结束，不再回退点击任意圈圈。非追新模式仍按配置中的固定调查战略选择。

## 菲林目标的局内策略

以下开关都在内置配置 `config/lost_void_challenge/菲林收集.sample.yml` 里，「通关效率」不开启。

- **同派系抱团**（`same_faction_first`）：「派系」指通用武备的分类，现有数据里有终结、异常·击破、机敏、绝境、携游五种（`lost_void_const.GENERAL_GEAR_CATEGORY_LIST`），同派系鸣徽的分类名与派系名相同。开局追新选中通用武备后，把派系记入 `LostVoidContext.gear_faction_list`；代理人武备仍按原来的方式加入战斗组优先级。
  - 「同派系」按本局**已有**的通用武备算（`get_owned_gear_faction_list`）：开局派系排最前，再加上本局记录里拿到的通用武备派系。因为鸣徽只能升级同派系武备，局内新拿的武备也要算；从本局记录读，程序中途重启后也不会丢。
  - 动态优先级里有按队伍追加的代理人类型（如全队异常角色会追加「异常」，按分类模糊匹配会命中「异常·击破」鸣徽），排在第0级之后，不会盖过已有武备派系。
  - `get_artifact_by_priority` 在每组（主选/次选）里先排「第0级(已有武备派系)」，再排 NEW 和第 1~4 级；第0级跟着 `consider_priority_1` 放行，所以邦布商店第一轮就会买同派系鸣徽。
  - 通用选择（`LostVoidChooseCommon.select_by_layers`）的点击顺序为：同派系 → NEW → 优先级。局内遇到的武备和鸣徽都走这里。
  - 选鸣徽时（`LostVoidChooseCommon.try_refresh_for_gear_faction`）：候选里没有已有武备派系的鸣徽，就点右上角「刷新」，直到出现为止；NEW 不算，照样刷新（用户定）。右上角剩余次数（`文本-刷新次数`，「× 5」，用完显示「× 0」）为 0 或识别不到、刷新后次数没变少时才按上面的顺序选。卡牌、武备、答题和没识别出来的候选不刷新。点刷新不弹确认框，直接换一批（2026-10-22 用户确认）。
  - 每局开始（`出战`、`矩阵行动-开始挑战`）调用 `reset_for_new_challenge()`，清空派系和动态优先级，避免上一局的派系带到下一局。
- **路线**：`region_type_priority` 为 武备格 → 限时格 → 金币格 → 邦布商店 → 偶遇事件 → 其余，按地图规划时用它给路线打分（见「路线规划」）。
- **邦布商店**（`LostVoidBangbooStore`）：刷新费用依次 50 → 100 → 200 → 300 硬币。
  - 刷新次数：除第三层终结之役前的最后一个休息区（本局第 3 次挚交会谈，`LostVoidContext.is_last_rest_area`，按本局记录的区域算，程序中途重启也不丢）外，花 200 硬币刷新一次（第 3 次，`lost_void_const.STORE_MAX_REFRESH_TIMES`）后就不再刷新；最后一个休息区不限次数，刷到硬币不够为止，货架买空也刷新再看。
  - 硬币留底：每次刷新前识别右上角硬币数量（`区域-硬币数量`）和右下角刷新费用（`区域-刷新费用`），刷新后剩下的硬币少于鸣徽最低价 600（`lost_void_const.STORE_MIN_ARTIFACT_PRICE`）就不刷新，按「不能再刷新」处理；所有商店都适用，识别不到数字时按刷新次数规则走。
  - 买什么：还能刷新时只买第0级(已有武备派系)、NEW、第1、2级，配置二（如「通用」）和优先级以外的宁可刷新也不买（2026-10-22 实测最后休息区第 3 轮还剩几千硬币就先买了 3 个通用鸣徽）；不能再刷新时：其他商店花 200 硬币刷新后（或硬币不够刷新）只买已有武备派系的鸣徽，没有或买完就离开，不买通用等其他鸣徽，硬币留到最后一个休息区（避免到了最后休息区商店没硬币）；最后一个休息区硬币不够刷新时不管优先级都买。
  - 往右看：经商友好战略等会增加商品槽位，一屏放不下。左边没有想买的（或已买完）就把货架一次拖到最右边（拖 1500 像素，到底后不会再动），刷新确认后拖回最左边再看。原来只拖 400 像素（约一张卡），最右边的商品总被漏掉（2026-10-22 实测）。
- **换战略**：沿用追新模式，按战略列表画面上的等级标记选没刷满的战略，不按固定武备数量判断。
- 作战潜能加点、战地邂逅、勘破迷踪需要手动完成。

## 路线规划（按地图）

完成悬赏委托目标不规划（`route_plan_enabled`），直接按配置的 `region_type_priority` 选画面里的门；其余目标都由程序看 Tab 地图规划。

- **什么时候规划**：感叹号 NPC 处理完、看到下层入口准备过去时，如果需要规划（`route_plan_pending`），就打开菜单（默认是地图页）规划（`LostVoidContext.need_route_plan` / `plan_route_by_map`）；正好要打开菜单更新动态优先级时在同一次里规划。需要规划的情况：第一层入口、进入新区域时路线已经空了（进入第 1、2 次挚交会谈会清掉上一层路线、没按规划走、规划的路线走完）。每个区域最多规划一次。第 3 次挚交会谈之后直接是终结之役，不规划。
- **识别地图**（`context/lost_void_map_reader.py`，画面特征见 [迷失之地画面·地图页](../../../../game/screens/迷失之地.md#迷失之地-藏品面板地图页)）：只看右边 MAP 一栏；彩色图标扩大后连成一块算一个节点，亮的是还能走到的，暗的是走过或走不到的；亮的节点用 `assets/template/lost_void/map_icon_*` 模板匹配类型（带骷髅角标的武备盾 = 环境战吼，单独一个模板，类型还是战斗-武备），先按一个大图标匹配，匹配不上按几个小图标匹配（混合节点）；发光圆圈里的是当前位置；最上面的 THRONE 是终点，进去是战斗-道中危机；节点之间的灰色虚线一段段串成整条线（弯的也行），线两头往外指向哪个节点就是连到哪个节点。识别结果按文字写进日志（`LostVoidMap.describe`）。
  - 第三层 THRONE 下面是最后一个挚交会谈，图标是白色的，彩色掩码找不到；在最上面一行彩色节点和 THRONE 之间按大的灰白色块找（`_find_white_top_node`）。之前漏了它，最上一行节点都是「往上连到：无」。
  - 节点右上角的环境角标（骷髅 / 毒雾）是白色圆块，灰色边缘会混进虚线，把往右上方的线头带偏、连不上。角标位置固定（节点中心右上 `BADGE_OFFSET`），圆里白色像素够多就把这一块从虚线里擦掉。2026-10-22 实测第二层漏了 武备→收割、第三层漏了 武备→限时，都是这个原因。
  - 串线时每段短线往前、往后各只接最顺的一段，两段互相选中才连上。之前只要求方向差 30° 以内，从同一个节点出发、夹角十几度的两条线会串成一团，两头数不清就整团丢掉。
  - 线从别的节点旁边经过时，那一截被节点周围的擦除范围切断。线头延长线离节点中心超过 `PASS_BY_DIST`（大节点按半径一半）算经过、不算连到（实测连到的线不超过 14 像素，经过的 20 以上；起点走过后只剩对勾，中心对不上，不判断）。断开的两截线头方向相对、离得不远就接成一条；后一截整个被擦掉（比如终点是当前位置的大圆圈）时，顺着线头往更远处找正对着的节点。
  - 同一行的节点之间不连线（地图只往上走）。
- **选路线**（`LostVoidMap.find_best_route`）：从当前位置往上把每条路线都列出来，按挑战配置的 `region_type_priority` 比较：先比路线上最优先那种区域的个数，多的更好；一样多再比第二优先的，依次类推；全一样取先找到的。混合节点按里面最优先的类型算，不在优先级里的类型（如代价之间、挑战-收割、休憩调息）不算数。菲林目标是 武备格 > 限时格 > 金币格 > 邦布商店 > 偶遇事件 > …；业绩点 / 悬赏用「通关效率」，偶遇事件最优先。
- **当前房间会忽略的门**：寻路会忽略本房间已交互过的类型（`LostVoidRunLevel.had_been_list`，例如挚交会谈里和玛琳交互后会加入偶遇事件，因为她头上的图标识别成偶遇事件）。这些类型的门第一步不走，否则锁定会被跳过、寻路去了别的门（2026-10-22 实测规划去偶遇事件，结果进了挑战-收割）。
- **转成寻路要找的入口**（`_route_to_region_type`）：混合节点的门上有几个图标，选一个同一步其它门上没有的类型，避免走错门。同一步还有别的门是同一种类型时（比如两个战斗-鸣徽），寻路分不清该进哪扇，路线就停在这一步，进去后再看地图从实际位置重新规划（2026-10-22 实测第一层两扇战斗-鸣徽，规划的是左边，寻路进了右边，后面整条路线作废）。
- **选门**（`get_entry_by_priority`）：先找规划的下一个区域，画面里没有时按配置的 `region_type_priority`，都没有就选最右的入口。
- **锁定规划的入口**（`LostVoidMoveByDet.locked_entry_name`）：去下层入口时锁定规划的下一个区域，当前画面里看不到也锁定（规划完关闭菜单时规划的门经常不在画面里，不锁就会直接去看得到的门）。寻路全程只认这种入口，不与相邻入口合并成混合入口（混合入口中心在两扇门之间，可能进错门）；判断到达时也只看锁定入口的图标有没有变大，站在别的门旁边不算到达（2026-10-22 实测站在战斗-鸣徽门边直接进了，没去规划的偶遇事件）；撞墙脱困后看不到它就原地转向找（默认左转；脱困横移过就往横移的反方向转，见下方「脱困动作」），看到别的门也不去。过不去时解除锁定、按画面里的入口选：连续 10 次无目标处理（约转一圈）没看到，或锁定后卡住 6 次（本层上限 12 次的一半）。
- 进入的区域与规划第一步一致就往前推一步；不一致就清空，下个房间去入口前重新规划（`on_enter_region`）。
- debug 模式下每次打开菜单都把地图截图存到 `.debug/lost_void_map/` 用来核对，样本够了要清理。离线核对识别结果：`.debug/temp/lost_void_map_read_eval.py` 把节点、类型、连线画在截图上（WSL 侧脚本，不随 git 同步）。

## 周期增益

战线肃清出战前的「选择周期增益」固定按内置配置 `period_buff_no` 选，默认「第二个」（`通关效率.sample.yml` 和 `菲林收集.sample.yml` 都是）；特遣调查没有这一步。挑战配置只读内置文件，用户不能改。曾经的 AI 决策已经删除，不再按队伍成员选。

## 计划刷取次数

运行页「计划刷取次数」（`LostVoidConfig.plan_run_times`，1~99，默认 1）。

- 每次通关后（节点「通关后处理」）`LostVoidRunRecord.add_complete_times()` 同时让 `plan_done_times` 加 1。
- `LostVoidRunRecord.plan_finished`（`plan_done_times >= plan_run_times`）为真时，节点「识别悬赏委托完成进度」返回 `STATUS_ENOUGH_TIMES`，不再开新的一局。三个刷取目标都生效，悬赏委托目标与「8000/8000」谁先到谁停。
- 到次数停止后，下次点开始时节点「初始化加载」把 `plan_done_times` 清零重新计数；改计划次数、点「重置记录」、跨周重置也会清零。
- `plan_done_times` 和周通关次数 `weekly_run_times` 是两回事：前者是「本轮计划」，后者是每周累计。

## 活性增幅

战线肃清·难度五画面底部有「以太活性：无活性增幅  n / 9」一栏，点右边的箭头在周期增益列表和活性增幅列表之间切换（画面说明见[迷失之地画面·战线肃清](../../../../game/screens/迷失之地.md)）。运行页「活性增幅」选方式（`aether_activity_mode`）：

- **不选**（默认）：不碰这一栏。活性越高敌人越强，自动战斗容易失败。
- **指定点数**：选到 `aether_activity_target`（1~9）点为止。
- **自动选满**：目标按 9 点算，选不动（剩下的都是「LOCK」未解锁，或列表到底）就停。

只在刷取目标是「获取大部分菲林奖励」时生效。流程在节点「选择活性增幅」（在「选择周期增益」之后、「下一步」之前）：

1. 第一行右边没有「500」或「LOCK」标签，说明还在周期增益列表，点箭头切过去。
2. OCR `文字-以太活性点数` 读「n / 9」；已达目标就结束。
3. 读 4 行的文字和右侧标签（`活性增幅-行N`、`活性增幅-行N-开关`），跳过空行、「LOCK」行和已经点过的行，点第一个可点的行。
4. 点完再读点数：变多 = 选中；变少 = 点到了已选中的行被取消了，再点一次还原；没变 = 这行点不动。已点过的行记在 `_activity_tried` 里，不再点。
5. 当前屏没有可点的行就把列表向下拖一次；拖完内容没变说明到底了，按现状继续。
6. 最多点 24 次（`MAX_CLICK_TIMES`），防止识别异常时一直点；超限也按现状继续，不让整次运行失败。

判断逻辑（读点数、判断锁定、选哪一行、点击效果）是 `lost_void_aether_activity.py` 里的纯函数，测试见 `tests/zzz_lv/application/hollow_zero/lost_void/test_lost_void_aether_activity.py`。

## 本局记录

`context/lost_void_run_memory.py`，同派系判断要用。

- 记录内容：经过的区域（`on_enter_region`）、拿到的藏品（通用选择点确定时的已选项、入口武备携带成功、商店购买确认后）以及按派系统计的鸣徽数量、商店记录（每个商店刷新几次、买了什么）。
- 通用选择记录已选项：先看画面上的「已选择」标记；「请选择1项」这类画面认不出标记时，用最后点的几个候选（2026-10-22 实测战斗-武备奖励选的溶剂弹射枪、浩劫令牌都因此没记上，同派系判断一直只有开局的终结）。
- 候选识别后按分类和名称对上藏品数据（`LostVoidContext.find_artifact_data`，名称允许个别错字），用数据里的是否武备、等级。对不上时保留 OCR 文字、等级记为 `?`。局内拿到的通用武备靠这里的「是否武备」算进「已有通用武备的派系」（`get_owned_gear_faction_list`），之后它的同派系鸣徽也会优先。
- 每次更新都写到 `config/{实例号}/lost_void_run_memory.yml`。程序中途关掉、再从大世界接着跑时会读回来，事后也能查看。
- 清除时机：`出战` / `矩阵行动-开始挑战` 时清空；本局结束时（`LostVoidRunLevel` 返回「通关」，通关和失败退出空洞都是这个状态）删除文件。其他失败（如超时）可能还在局内，不清除。
- 最后一个休息区 = 终结之役前的挚交会谈：数区域记录里的挚交会谈，第 `LAST_FRIENDLY_TALK_TIMES`（3）次就是最后一个。

## 层间移动与入口交互

**层间移动 `LostVoidRunLevel`**(`lost_void_run_level.py`):核心循环 = `非战斗画面识别`(YOLO `detect_to_go` 找 感叹号/白点/下层入口,按优先级移动)→ `try_interact`(interact F)→ `handle_interact`(**按画面路由**:武备选择→`LostVoidChooseGear` / 通用选择→`LostVoidChooseCommon` / 邦布商店→`LostVoidBangbooStore` / 路径迭换→`LostVoidRouteChange` / 抽奖机→`LostVoidLottery` / 挑战结果→结算(标题被进度条盖住时用「总计用时」兜底,且要在对话判断之前) / 否则对话/黑屏兜底)→ `after_interact`。战斗走 `init_auto_op` → `in_battle`(自动战斗 + 识别脱战)。失败兜底:`handle_find_target_fail` → `push_error` → `fail_exit_lost_void`。

**战斗结束判断**(`in_battle`,道中危机和终结之役以外的战斗):打完后会出现指向下一处的白点,下面带「23.5m」这样的距离文字(见[玩法文档](../../../../game/gameplay/迷失之地.md))。每 0.8 秒用 OCR 在 `战斗画面-距离显示区域` 读距离文字(`auto_battle_context.check_battle_distance`),读到一次就停止自动战斗、回到非战斗画面识别,和右上角「前往下一个区域」一样。只靠 YOLO 认白点时要置信度 0.9 且连续 10 次,战斗中镜头晃动很难满足;2026-10-22 实测复杂区域打完第一个房间后一直打空气,直到手动暂停。

**检测前涂黑界面**(`LostVoidDetector.mask_hud`,`HUD_MASK_RECT_LIST`):YOLO 推理前把容易被误检的界面区域涂黑,所有调用迷失之地检测的地方都生效。目前两块:左上角色头像;右上通知列前两条的圆形图标(见[画面文档「右侧通知列」](../../../../game/screens/迷失之地.md#迷失之地-大世界))。后者的来历:2026-10-22 寻路采样 5 局里,交互结束回到大世界后追感叹号时原地转 7 次没找到的有 13 次(每次约 19 秒),其中 6 次的首帧目标就是这个图标,另 6 次推测同因但截图没存下。离线用采样截图对比(`.debug/temp/hud_mask_check.py`,Windows 端):涂黑区域内的误检 24→0,其他 400 帧在涂黑区域外的识别没有变化。

**移动用的角色**(`auto_battle_utils.switch_to_best_agent_for_moving`):每次开始移动和脱困前切到队伍里最适合移动的角色。按 `_get_agent_priority` 的优先级选,身高不会挡住入口图标的同时速度越慢越好。

**对准目标**(`LostVoidMoveByDet.turn_to_target`):转向量 = 目标离画面中心的横向像素 × 转向比例(鼠标移动量 ÷ 目标横移像素)。比例存在 `ctx.lost_void.move_turn_ratio`,初始 0.6(2026-10-22 寻路采样里单次转向实测中位数,四分位 0.50～0.64),每次原地转向后用目标实际横移的像素平滑更新(本次占 0.2;横移不到 30 像素或测出的比例不在 0.3～1.2 时不采用,多半是识别框跳了或换了目标),跨移动保留。原地转向到目标离中心 50 像素以内再起步,之后边走边修正(移动中每次最多转 15);单次最多转 600。2026-10-22 曾改成离中心 120 像素就起步,当晚实测第一层第一间连续撞上入口前路障(下午同一入口用 50 像素的 5 局都没这样),已改回 50。此前每次移动都把比例重置为 0.2、先试探转 5 再估算,起步前中位数要原地转 2.8 秒,5 局合计 432 秒。

**寻路卡住与脱困**(`LostVoidMoveByDet`,`lost_void_move_by_det.py`):寻路 = 镜头对准目标图标 → 按住 W 直线前进,没有提前避障,撞上障碍物后靠卡住判断 + 脱困补救。
- **卡住判断**(两种任一触发):① 画面静止(`check_scene_static`):按住 W 期间,把画面缩小 8 倍转灰度,排除角色区域和顶部/底部 HUD,与上一帧算平均差值;连续 1.5 秒低于 `SCENE_STATIC_DIFF` = 被挡住原地跑。正常跑动、转镜头时画面变化大,不会误判。阈值待实机校准,debug 模式下日志打印每帧差值。② 图标静止(`check_stuck`):画面里所有识别到的图标位置都不变,单个图标时要约 25 帧,较慢。
- **脱困动作**(`get_out_of_stuck`):后退 → 横移 → 前进。第 1 次脱困只横移;之后每多卡一次,先按 S 后退 `min(0.5 × 次数序号, 2)` 秒,横移后再按 W 前进 `min(0.2 × 次数序号, 2)` 秒(次数序号 = 本段卡住次数 − 1,时长见 `get_escape_durations`)。加回后退和前进的原因:只横移遇到宽障碍或墙角会一直贴着障碍滑,脱不了困(2026-10-23 反馈),做法参照上游同名节点。普攻和切换移动角色仍不做。以下是其中横移的细节(`_strafe_facing_target`):只按住 A/D 横移,横移期间不断识别目标、转镜头让目标保持在画面中心(每次最多转 100,看不到目标时只横移不转),这样 A/D 始终垂直于目标方向,绕着目标沿障碍物边缘移动;横移完回到「移动前转向」重新对准目标。此前还有普攻、后退 0.4 秒、前进 0.6 秒、切换移动角色,实际看到角色掉头往身后跑,2026-10-22 按用户要求去掉,只留横移。横移后仍丢失目标时「无目标处理」往横移的反方向转着找(向左横移就右转)。横移时间 `min(0.8 + 0.4 × (本段移动卡住次数-1), 2.5)` 秒,按本段移动计数,不按本层累计:此前按本层累计,前一段移动卡过一次,下一段第一次脱困就横移 1.2 秒以上,横移过头丢了目标(2026-10-22 第一层第一间鸣徽入口前实测)。
- **方向**:同一方向连续绕行 2 次仍卡住才换另一侧(此前每次左右交替,位移互相抵消,宽障碍物永远绕不过去);换边后横移更久,能覆盖到更远位置。按键依次按,不同时按 W+A(后台手柄模式下两个方向会互相覆盖)。
- 本层卡住超过 12 次 → 寻路失败。
- **深度避障**(运行页「深度避障」开关 `depth_avoid_enabled`,默认开):用单目深度模型 Depth Anything V2 Small 提前绕开障碍物,撞上之前就转向。
  - 模型手动放到 `assets/models/depth/depth-anything-v2-small/model.onnx`(暂无发布包,不自动下载);没放置、关掉开关或本机没有 GPU 执行提供程序(CUDA / DirectML)时寻路不避障,只靠上面的卡住判断 + 脱困。**深度模型只用 GPU 推理**,不再跟随迷失之地识别模型的 GPU 开关(`lost_void_det_gpu`),也不退回 CPU:移动中每帧都要用,CPU 跑不动,拖慢整个寻路(`LostVoidDepthEstimator.is_gpu_available`,不满足时日志「深度避障 | 没有可用的 GPU」)。推理经 `OnnxModelLoader.run_session` 走 `gpu_executor`。
  - 判断方法(`LostVoidDepthEstimator`):估计每个方向「脚下能走多远」。平地上模型输出的逆深度随画面行线性变化(越往上越远),先用角色两侧画面下方的地面拟合出这个变化率;墙、栏杆、箱子、NPC 这类立着的东西往上看深度不再变化,竖直变化率低于地面的 35% 就算立着。1080p 下 x 160~1760 分 16 列,每列从下往上扫,第一个立着的东西所在的行就是这个方向能走到的位置,行越靠下越近,在 y 600 以下算近处挡路。两次推理至少间隔 0.3 秒,期间复用上次结果;技能特效铺满画面导致地面拟合失败时这一帧不判断。
  - 局限(2026-10-22 用 5 次卡住、20 张卡住前后截图离线验证):角色所在的列只能从头顶往上看,正前方脚下被角色身体挡住,直线撞上的矮障碍(如第一层第一间入口前的便携路障)看不到;角色两侧近处有障碍的情况在正常奔跑中也有约 43%(沿墙跑、跟随的邦布、NPC),不能单独当作「要撞了」。
  - 跑动中偏转(`_get_avoid_aim_x`):目标图标所在列近处挡路时,在目标附近 6 列内按「障碍所在行 + 偏离目标的列数 × `AIM_DIR_COST`(15)」挑代价最小的不挡路列(`LostVoidDepthEstimator.choose_aim_column`),把瞄准点从图标偏到那一列中心;上次选的列仍不挡路、代价比最优列多不超过 `AIM_KEEP_MARGIN`(30)就继续用,避免来回摆;角色所在的列(从头顶往上扫,看不到脚下)不作为候选。此前是从近到远找最近的不挡路列,一旦发现一列刚好不挡路就选它,不看那一列后面是不是更堵。偏转时每次最多转 40(平时 15)。目标在角色所在的列、附近都挡、或目标图标已大于 50 像素(快到了)时不干预。只决定往哪边偏,不决定走几步:相对深度没有真实距离,移动仍是按住 W 每 0.1 秒重新识别修正。日志「寻路避障 目标方向被挡 偏向第N列 / 前方空了 恢复对准目标」。
  - 脱困选边(`_get_escape_side`,每次寻路第一次脱困时):**深度优先,图标兜底**。先比较角色左右两侧各列障碍所在行的平均值(`pick_escape_side_by_depth`),两侧相差不少于 `ESCAPE_DEPTH_MIN_DIFF`(20 行;2026-10-23 同一路障场景,录像离线测得右侧比左侧大 49～53,实机第一次脱困测得 27,所以由 40 降到 20;其他场景实机见过两侧差 100 以上的情况,不受影响)就往障碍更远的一侧横移;深度模型没放置、关掉深度避障或两侧差别不大时,退回「目标图标偏离画面中心 10 像素以上就往图标所在一侧横移」(入口在障碍物后面偏哪边,从那边绕最短,这一条不依赖深度模型。2026-10-22 第一层第一间路障卡住时图标偏右约 15 像素,往右横移后通过)。之后仍按同侧 2 次再换边。
  - 改成深度优先的原因(2026-10-23 录像):第一层第一间选右边入口时,入口在栏杆和墙围出的小角落里,只能从路障左前方绕进去;图标略偏右,旧规则先往右绕,钻进路障和右侧铁皮墙之间的窄死角,退出来再往左绕,多花约 16 秒,布局固定每次都这样。日志「寻路脱困 深度判断 …」或「寻路脱困 目标偏左/右 N像素 往目标一侧绕」。
  - 调参:离线评估脚本 `.debug/temp/lost_void_depth_freespace.py` 直接调用 `LostVoidDepthEstimator`,对下面的采样截图输出每列障碍位置的可视化图和「卡住前后 / 正常奔跑」两组的近处挡路比例,改参数后用它核对。
- **避障采样**(仅 debug 模式):移动中每 3 秒保存一张截图;判定卡住时保存当前画面和卡住前 1/2/3 秒的画面(正在接近障碍物)。都存为 jpg,放在 `.debug/lost_void_depth/raw/`,截图已遮挡 UID。之后用 DeepSeek 离线标注「正前方是否被挡」,再评估深度模型。debug 模式下长时间运行会持续占用磁盘,采样够了要清理。
- **寻路采样**(开发工具应用「迷失之地寻路采样」`lost_void_navigation`,在应用运行页选它,或后端 `POST /game/run/standalone?app_id=lost_void_navigation`):沿用迷失之地的配置、队伍和副本,只跑一局,回到入口就停;运行记录只在内存里,不动真实周常进度,周常已完成也照样跑。用来对比寻路改动前后每局花在移动上的时间。
  - 输出在 `.debug/lost_void_navigation/runs/<run_id>/`:`events.jsonl` 逐行一条事件,`images/` 是移动中每秒一张截图(UID 已涂黑)。
  - 事件:`run_start/run_end`(一局,终态 normal/failed/interrupted)、`level_end`(一层)、`move_start/move_end`(一次 `LostVoidMoveByDet`,`move_end.outcome` 为 arrived 按到达条件结束 / target_changed 目标消失或交给上层重识别 / combat / failed / interrupted)、`stuck`(触发脱困,`reason` 区分 scene_static 按住前进画面不动、icon_static 目标图标不动、target_lost 移动中多次丢目标、search_exhausted 原地转 7 次没找到)、`action`(实际发出的按键与转向)、`frame`(截图路径和当时追踪的目标框)。
  - 只有这个应用运行时 `ctx.lost_void.navigation_session` 才有值,正常运行迷失之地不记录。

**入口层重复交互防护**(2026-08-20 首版,2026-08-26 按实测机制重写走位,对应玩法文档「入口层交互机制」):
- 入口层构造 `LostVoidChooseGear` 时传共享名单 `entry_gear_name_list`;携带成功后把画面**首个**武备名记入名单;再次进入武备选择画面时先只点首个武备读名字,difflib(cutoff=0.8,只容忍同名 OCR 错字)命中名单 → 直接点返回退出(约 4 秒,状态 `重复武备选择`),不再重复整套识别(约 40 秒)。判断信号与存储信号对称(都是画面最左侧槽位的武备名,最左格 OCR 解析失败则本画面不记录)。**名单已有 2 个武备名时再进武备画面必为重复,直接退出**(入口层只有两个武备 NPC,连点首格读名都省掉)。
- **按键前闭环校验**(完成过首次交互后,每次按交互键前):OCR `区域-交互文本` 读「> 名字 <」标签确认按下会命中谁——文本是入口(含混合入口的「复杂区域」,`MIXED_ENTRY_NAME`;此时下层类型沿用寻路识别的入口图标)或**没交互过的目标**才按;是已交互 NPC 或读不出时不按,改为走位换目标后重试(上限 8 次,确认到目标后清零)。
- **走位换目标**(`_steer_towards_other_interact_icon`):用当前标签的 x 坐标排除已瞄准的感叹号图标,朝剩余图标里最大(=最近)的一个迈步(先前进 0.18 秒收距离,再按水平偏移横移,偏得越多步子越大,`min(0.3, 0.1+|dx|/800)` 秒),让朝向指向目标,下一轮标签即切换。找门阶段(感叹号已忽略/放弃)则直接朝**下层入口图标**迈步;什么图标都检测不到才前进+左右交替兜底。
- 完成一次武备选择后后退 0.8 秒,让相邻感叹号进入画面再接近(首版的「贴近 NPC+横移」会因取最右侧图标而走向刚交互完的 NPC,已废弃)。
- **三个 NPC(两武备+研究员)都交互完成后,主动把 `感叹号` 加入 `had_been_list` 直接找下层入口**——剩余感叹号已无价值,不再走过去,避免去门途中被 NPC 反复抢交互(实测最坏一轮从 981 秒收敛到 248 秒)。
- 走位重试达上限时:标签明确是已交互 NPC 就**不硬按**(硬按必进重复画面白费 40 秒+),后退 1.2 秒换角度重新接近;只有标签读不出才硬按兜底(可能是门没读出标签),错按由判重退出自愈。
- 重复退出累计 3 次 → 放弃感叹号直接找下层入口(最后兜底,宁可丢研究员礼物也不卡死)。
- 入口层完成过武备选择后,走向剩余感叹号的移动超时(感叹号被桌子/栅栏遮挡走不到)同样转为放弃感叹号直取下层入口,不再直接重开整层(重开后大概率同样走不到);一个武备都没选到时保持重开(重摇布局)。
- 超时重开:`handle_find_target_fail` 重开挑战成功后置 `attempt_start_time` 重新计时(此前重试沿用 `operation_start_time`,超时触发的重试会立刻再次超时,3 次全废),并清空本层交互状态与脱困计数(`stuck_state`,重开后位置已重置,旧计数会让新一轮直接放弃寻路)。

**通用选择决策(`LostVoidChooseCommon`)**:OCR 标题定子态与需选数 → 四层选择策略(同派系 → NEW → 优先级 → 答题兜底 → 盲点兜底;候选名没识别出来时按盲点兜底),选满 N → 点确定(解析按钮 `(x/y)` 计数判断选满)。
